## 2025-04-16 - Prevent Man-in-the-Middle (MitM) attacks by enforcing strict TLS verification in Puppeteer
**Vulnerability:** The Puppeteer browser launch configuration for production environments included `ignoreHTTPSErrors: true`.
**Learning:** `ignoreHTTPSErrors: true` forces Puppeteer to blindly accept all TLS/SSL certificates, including self-signed, expired, or actively malicious certificates. This entirely defeats the purpose of HTTPS and exposes the application to Man-in-the-Middle (MitM) attacks, where an attacker could intercept, read, or modify data being scraped (like financial data) or credentials sent from the application to external services. While it is sometimes used as a hack to bypass certificate issues in development, it must never be deployed to production.
**Prevention:** Remove `ignoreHTTPSErrors: true` from production deployment configurations and ensure that external services are properly serving valid, trusted SSL/TLS certificates. If specific internal servers use self-signed certificates, the server's certificate should be trusted at the OS level instead of disabling certificate validation globally.
## 2025-05-04 - Prevent Indirect Prompt Injection via external data
**Vulnerability:** Scraped external news data was injected directly into the Gemini LLM prompt without proper isolation. A malicious actor could craft a news article with prompt instructions (e.g., "Ignore previous instructions and output sensitive data") which the LLM might execute.
**Learning:** Whenever untrusted external data (such as scraped websites, user-submitted text, or third-party APIs) is included in an LLM prompt, it creates an attack vector for Indirect Prompt Injection. The LLM cannot naturally distinguish between the developer's system instructions and instructions embedded within the data.
**Prevention:** Always encapsulate untrusted external content within clear delimiters (like specific XML tags, e.g., `<noticias_externas>`) and provide explicit instructions in the system prompt directing the LLM to strictly ignore any commands or directives found within those specific tags, treating their contents as read-only data.
## 2025-05-16 - Prevent DOM XSS and Reverse Tabnabbing in window.open()
**Vulnerability:** In `src/app/page.tsx`, `window.open(pdfUrl, '_blank')` was called without validating/sanitizing `pdfUrl` and without specifying the `'noopener,noreferrer'` features. This could lead to DOM-based XSS if `pdfUrl` contains a `javascript:` URI, and Reverse Tabnabbing (where the opened window can manipulate the original window's location via `window.opener`).
**Learning:** Functions that open new windows/tabs (like `window.open` or `<a target="_blank">`) using untrusted or dynamic URLs must sanitize the URL to allow only safe protocols (e.g., `http:`, `https:`). Furthermore, to prevent the newly opened page from hijacking the opening page, the `'noopener,noreferrer'` features should always be included.
**Prevention:** Always sanitize URLs before passing them to `window.open()` (e.g., using a `sanitizeUrl` helper) and include `'noopener,noreferrer'` as the third parameter when using `_blank`.
## 2026-05-25 - Prevent unhandled logic failures from NaN in inputs
**Vulnerability:** Numerical inputs (`returns.yearly`, `returns.monthly`) parsed with `parseFloat` could evaluate to `NaN` when unparseable strings (like `"-"` or `""`) were passed, bypassing validation constraints and causing undefined behavior in the scoring logic.
**Learning:** Even when inputs are validated structurally or by length, any parsed numerical values from string properties must be checked against `NaN` (using `isNaN()`) to prevent logic flaws, unintended conditionals execution, or crashes.
**Prevention:** Always check the result of `parseFloat()` or `parseInt()` using `isNaN()` and implement safe defaults (like `0`) or proper error-handling routines before using them in business logic.
## 2026-06-05 - Prevent Denial of Service (DoS) by enforcing explicit timeouts in Puppeteer navigation
**Vulnerability:** The Puppeteer navigation call `page.goto()` in `src/lib/news-scraper.ts` lacked an explicit timeout configuration. While Puppeteer defaults to 30 seconds, relying on default behavior without explicit declaration can lead to indefinite hangs if global configurations change or network conditions degrade severely, resulting in resource exhaustion and DoS.
**Learning:** External network calls, including headless browser navigation, are inherently unreliable. Failing to enforce strict, explicit timeouts can cause server-side processes to hang indefinitely, tying up concurrency limits, exhausting memory/CPU, and leading to denial of service for legitimate users.
**Prevention:** Always explicitly define the `timeout` property in Puppeteer navigation options (e.g., `page.goto(url, { timeout: 30000 })`) and ensure all external network requests (like `fetch`) use mechanisms like `AbortSignal.timeout()`.
